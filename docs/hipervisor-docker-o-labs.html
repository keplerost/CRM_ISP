Hipervisor: Docker o laboratorios

Cómo encender y apagar el hipervisor de Windows para alternar entre Docker y EVE-NG / GNS3. Los comandos exactos, dónde pegarlos y cómo comprobar que funcionó.

Equipo · Intel i7-7700 VMware · Workstation 17.6.2 VirtualBox · 7.1.6 Estado inicial · hypervisorlaunchtype Off

01 Por qué hay que elegir

Solo un programa a la vez puede quedarse con las instrucciones de virtualización del procesador (VT-x). Cuando el hipervisor de Windows está encendido, se las queda él y se las presta a los demás — y esa prestada alcanza para casi todo, menos para lo que más te importa.

Con el hipervisor…EncendidoApagado
Docker Desktop / WSL2FuncionaNo arranca
VM comunes
DNS-AdGuard, TEAMWORLD		Funcionan, algo más lentasFuncionan
EVE-NG y GNS3Fallan o van muy lentosFuncionan

EVE-NG y GNS3 necesitan virtualización anidada: la máquina virtual tiene que poder virtualizar adentro, porque cada router del laboratorio es a su vez una máquina. Esa capacidad es la primera que se pierde cuando Hyper-V se adueña del procesador.

Por eso estaba apagado

La configuración que tenías no era un error: alguien la puso así para que los laboratorios anduvieran. Si tu prioridad son EVE-NG y GNS3, dejarlo apagado sigue siendo lo correcto.

02 Abrir PowerShell como Administrador

Todos los comandos de esta ficha lo necesitan. Sin permisos de administrador, bcdedit contesta «Acceso denegado».

1

Tecla Windows y escribí powershell

2

Botón derecho sobre Windows PowerShell → Ejecutar como administrador

3

Aceptar el aviso de Windows

La ventana correcta dice «Administrador:» en la barra de título. Si no lo dice, cerrala y repetí.

03 Encender el hipervisor — para usar Docker

Pegar tal cual

bcdedit /set hypervisorlaunchtype auto

Tiene que contestar:

La operación se completó correctamente.
Hay que reiniciar

El cambio se aplica en el arranque, no en el momento. Hasta que reinicies, Docker va a seguir diciendo «Virtualization support not detected».

Después de reiniciar, comprobar

Get-CimInstance Win32_ComputerSystem | Select-Object HypervisorPresent
HypervisorPresent
-----------------
             True   ← así tiene que quedar

Y ahora sí, Docker:

docker info --format "{{.ServerVersion}}"

04 Apagar el hipervisor — para los laboratorios

El camino de vuelta, para cuando necesites EVE-NG o GNS3.

Pegar tal cual

bcdedit /set hypervisorlaunchtype off

Reiniciar y comprobar

Get-CimInstance Win32_ComputerSystem | Select-Object HypervisorPresent
HypervisorPresent
-----------------
            False   ← los laboratorios vuelven a andar
Es reversible siempre

Ir y volver entre auto y off no rompe nada ni deja rastro. Es un interruptor, no una operación delicada. Lo único que cuesta es un reinicio.

05 Elegir al arrancar, sin comandos

Si vas a alternar seguido, conviene esto: dos entradas en el menú de arranque. Prendés la PC, elegís, y no volvés a tocar bcdedit nunca más.

1

Duplicar la entrada actual:

bcdedit /copy "{current}" /d "Windows 10 (Docker)"

Devuelve un identificador entre llaves. Copialo, se ve así: 

La entrada se copió correctamente en
{a1b2c3d4-1234-5678-9abc-de1234567890}
2

A esa entrada nueva, encenderle el hipervisor. Reemplazá el identificador por el tuyo:

bcdedit /set "{a1b2c3d4-1234-5678-9abc-de1234567890}" hypervisorlaunchtype auto
3

A la de siempre, dejarla apagada y ponerle un nombre claro:

bcdedit /set "{current}" hypervisorlaunchtype off
bcdedit /set "{current}" description "Windows 10 (Laboratorios)"
4

Que el menú espere 10 segundos antes de elegir solo:

bcdedit /timeout 10

A partir del próximo arranque vas a ver:

  Windows 10 (Laboratorios)     ← EVE-NG, GNS3
  Windows 10 (Docker)           ← Docker, WSL2
Las llaves llevan comillas

En PowerShell, {current} sin comillas se interpreta como código y el comando falla o hace algo raro. Siempre "{current}" entre comillas dobles. En la ventana de Símbolo del sistema (cmd) no hace falta, pero ponerlas igual no molesta.

Para deshacerlo

Borra la entrada nueva y deja todo como estaba:

bcdedit /delete "{EL-IDENTIFICADOR-QUE-COPIASTE}"

06 Ver en qué estado estás

El comando que contesta la pregunta «¿hoy tengo Docker o laboratorios?»:

bcdedit | findstr -i hypervisorlaunchtype
Si contestaEstás en modo
hypervisorlaunchtype   AutoDocker · WSL2 anda, EVE-NG y GNS3 no
hypervisorlaunchtype   OffLaboratorios · EVE-NG y GNS3 andan, Docker no
NadaSin definir. Se comporta como Auto

Ese comando lee la configuración de arranque, no el estado real. Para saber qué está corriendo ahora: 

Get-CimInstance Win32_ComputerSystem | Select-Object HypervisorPresent

Si los dos no coinciden —la configuración dice Auto y HypervisorPresent dice False— es que falta reiniciar.

07 Cuando algo no sale

SíntomaCausaSolución
«Acceso denegado» PowerShell sin permisos de administrador Sección 2. La barra de título tiene que decir «Administrador:»
Docker sigue diciendo «Virtualization support not detected» Falta reiniciar Reiniciar. El cambio solo se aplica al arrancar
Reinicié y sigue igual Puede haber quedado en la otra entrada de arranque bcdedit | findstr -i hypervisorlaunchtype
VMware avisa que Hyper-V está activo Es correcto, no es un error Las VM comunes andan igual. EVE-NG y GNS3 no: para esos, modo laboratorios
EVE-NG no arranca sus nodos Perdió la virtualización anidada Modo laboratorios (sección 4) y reiniciar
El menú de arranque no aparece El tiempo de espera quedó en cero bcdedit /timeout 10
Si algo queda muy mal

El arranque de Windows se restaura entero con esto, desde una consola de administrador — vuelve al comportamiento de fábrica: 

bcdedit /deletevalue "{current}" hypervisorlaunchtype
