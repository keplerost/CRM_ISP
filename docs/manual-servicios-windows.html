01 La cadena, y dónde se corta

Para que el CRM pueda consultar una deuda, cuatro cosas tienen que estar vivas:

CRMen la nube
───▶
api.smartbotai.netDNS de Cloudflare
───▶
cloudflaredservicio
───▶
localhost:4000servicio
───▶
Supabasela base

Las dos del medio corrían a mano. Eso significa que después de reiniciar la PC había que acordarse de levantarlas, y que cualquiera que cerrara una ventana sin mirar dejaba al CRM sin API — en silencio, porque del otro lado eso se ve como un error de red cualquiera.

Como servicios, las dos arrancan solas y no tienen ventana que cerrar.

ServicioQué haceSi se cae
smartolt-api La API en el puerto 4000 El túnel contesta 502
cloudflared El túnel hacia Cloudflare El dominio contesta 530 o no responde
La distinción que ahorra media hora

502 = el túnel llegó pero atrás no hay nadie. El problema es smartolt-api.
530 o sin respuesta = no hay túnel. El problema es cloudflared.

02 El túnel como servicio

Con el túnel ya andando a mano —creado, con su config.yml y su DNS apuntado— el paso es uno solo, desde PowerShell como Administrador: 

& "C:\Program Files (x86)\cloudflared\cloudflared.exe" service install

Eso crea el servicio y lo pone en automático. Y acá es donde parece que terminó, pero no.

03 La trampa del ImagePath

Después de instalarlo, el servicio figura Running. Parece que anda. Pero el túnel dice otra cosa:

El proceso vive; el túnel no. Y la causa está en cómo quedó registrado el servicio:

Sin tunnel run. Y esta versión no arranca así — lo dice ella misma si se la corre con el perfil del servicio:

Arranca, lee la configuración, encuentra el túnel, y sale — porque nadie le dijo que lo corriera.

La corrección

Se escribe el ImagePath completo, como Administrador:

Set-ItemProperty -Path 'HKLM:\SYSTEM\CurrentControlSet\Services\cloudflared' `
  -Name ImagePath -Value '"C:\Program Files (x86)\cloudflared\cloudflared.exe" --config "C:\Windows\System32\config\systemprofile\.cloudflared\config.yml" tunnel run smartolt-api'

Y se comprueba que quedó:

Después de cada actualización

Un winget upgrade Cloudflare.cloudflared puede reinstalar el servicio y dejar el ImagePath pelado otra vez. Es lo primero que hay que mirar si un día el túnel deja de levantar solo.

04 El otro perfil de usuario

El servicio corre como LocalSystem, que no es tu usuario. Su carpeta personal no es C:\Users\Game1 sino: 

C:\Windows\System32\config\systemprofile

Así que el config.yml, el .json de credenciales y el cert.pem tienen que estar ahí también: 

$origen = "C:\Users\Game1\.cloudflared"
$destino = "C:\Windows\System32\config\systemprofile\.cloudflared"

New-Item -ItemType Directory -Path $destino
Copy-Item "$origen\config.yml"   $destino
Copy-Item "$origen\cert.pem"     $destino
Copy-Item "$origen\*.json"       $destino
El detalle que se escapa

Dentro del config.yml, la línea credentials-file: apunta a tu carpeta. Hay que reescribirla para que apunte a la copia nueva: 

credentials-file: C:\Windows\System32\config\systemprofile\.cloudflared\949e861d-….json

Copiar los archivos y olvidarse de esta línea deja el servicio buscando credenciales en una carpeta que no le corresponde.

05 La API como servicio

Node no sabe hablar con el administrador de servicios de Windows: si se lo registra directo, Windows lo arranca, no recibe respuesta, y lo mata. Hace falta un envoltorio. El estándar es NSSM. 

winget install --id NSSM.NSSM

Crear el servicio

nssm install smartolt-api "C:\Program Files\nodejs\node.exe" `
    "--env-file=middleware\.env middleware\src\server.js"

Configurarlo

nssm set smartolt-api AppDirectory      "G:\TALLER_SMARTOLT"
nssm set smartolt-api DisplayName       "SmartOLT API (middleware)"
nssm set smartolt-api AppStdout         "G:\TALLER_SMARTOLT\logs\middleware.log"
nssm set smartolt-api AppStderr         "G:\TALLER_SMARTOLT\logs\middleware.err.log"
nssm set smartolt-api AppRotateFiles    1
nssm set smartolt-api AppRotateBytes    10485760
nssm set smartolt-api AppExit Default   Restart
nssm set smartolt-api AppRestartDelay   5000
AjustePara qué
AppDirectory El más importante. Sin esto el servicio arranca en C:\Windows\System32 y no encuentra el .env ni el server.js, porque las rutas del comando son relativas.
AppStdout / AppStderr Sin ventana, los mensajes se pierden. Estos archivos son la única forma de saber qué pasó.
AppRotate… Corta el log cada 10 MB. Un servicio que corre meses llena el disco si no.
AppExit … Restart Si Node se cae, vuelve solo a los 5 segundos.
Antes de arrancarlo

Si tenías la API corriendo a mano, hay que bajarla primero: el puerto 4000 no lo pueden tomar dos procesos. 

Get-NetTCPConnection -LocalPort 4000 -State Listen |
  ForEach-Object { Stop-Process -Id $_.OwningProcess -Force }
Start-Service smartolt-api

Dos cosas que hay que verificar antes, no después

  • Que el disco sea local. LocalSystem no ve unidades de red mapeadas. Get-CimInstance Win32_LogicalDisk -Filter "DeviceID='G:'" tiene que dar DriveType 3.
  • Que el programa no dependa de tu carpeta de usuario. Si usa ~/.ssh, os.homedir() o %USERPROFILE%, bajo LocalSystem va a mirar en otro lado.

06 El orden de arranque

Los dos son automáticos, así que al prender la PC arrancan los dos — pero no necesariamente en orden. Si el túnel gana la carrera, contesta 502 unos segundos hasta que la API esté lista.

Se le dice a Windows que uno espera al otro:

Set-ItemProperty -Path 'HKLM:\SYSTEM\CurrentControlSet\Services\cloudflared' `
  -Name DependOnService -Value @('smartolt-api') -Type MultiString
Si el túnel arranca primero igual

No es grave y se arregla solo: cloudflared reintenta el origen en cada pedido, así que en cuanto la API levanta empieza a contestar. La dependencia solo evita esos primeros segundos de 502.

07 Comprobar que todo quedó bien

Cuatro comprobaciones, de adentro hacia afuera:

Si dice does not have any active connection, volvé al paso 3.

La prueba definitiva

Reiniciar la PC y no tocar nada. Si a los dos minutos api.smartbotai.net contesta 200, quedó bien. Es la única prueba que cubre todo.

08 El día a día

SituaciónQué hacer
Tocaste código del middleware Restart-Service smartolt-api — el servicio no recarga solo.
Querés desarrollar con recarga automática Stop-Service smartolt-api, después npm run dev. Al terminar, al revés.
Cambiaste el config.yml del túnel Copiarlo de nuevo al perfil de LocalSystem y Restart-Service cloudflared.
Ver qué está pasando Get-Content …\logs\middleware.log -Wait -Tail 20
Ver los errores Get-Content …\logs\middleware.err.log -Tail 30
El error que vas a cometer una vez

Editar código y no ver el cambio. El navegador se refresca solo; el servicio no. Con la API corriendo a mano al menos se veía la ventana; como servicio no hay ninguna señal. Ante cualquier «no toma el cambio»: Restart-Service smartolt-api.

09 Cuando algo falla

SíntomaCausaSolución
502 en el dominio El túnel llega, la API no está. Get-Service smartolt-api. Si está detenido, mirar middleware.err.log.
530 o sin respuesta No hay túnel conectado. cloudflared tunnel info. Revisar el ImagePath.
Running pero sin conexiones ImagePath sin tunnel run. Sección 3.
El servicio arranca y muere Falta el config.yml en el perfil de LocalSystem. Sección 4.
«no se pudo iniciar» sin más Node no encuentra el .env. Verificar AppDirectory: nssm get smartolt-api AppDirectory.
El puerto 4000 está ocupado Quedó un npm run dev vivo. Get-NetTCPConnection -LocalPort 4000 -State Listen y cerrar ese PID.
Dejó de arrancar tras actualizar El instalador rehizo el servicio. Revisar el ImagePath (sección 3).

Dónde mirar, en orden

  1. G:\TALLER_SMARTOLT\logs\middleware.err.log — los errores de la API.
  2. Get-EventLog -LogName Application -Source cloudflared -Newest 10 — el arranque del túnel.
  3. sc.exe qc cloudflared — cómo quedó registrado.

10 Deshacerlo

Todo esto se revierte. Como Administrador: 

Stop-Service cloudflared, smartolt-api
nssm remove smartolt-api confirm
& "C:\Program Files (x86)\cloudflared\cloudflared.exe" service uninstall

Y se vuelve a levantar a mano como antes: 

npm run dev
cloudflared tunnel run smartolt-api

Nada de esto toca el túnel ni el dominio en Cloudflare. El túnel, su UUID y el registro DNS siguen existiendo — lo único que se quita es el arranque automático de esta máquina.
