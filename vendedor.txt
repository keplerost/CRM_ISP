NUEVO REQUERIMIENTO PRIORITARIO — SEGURIDAD DE CARTERA, COBRANZA Y FLUJO DE INSTALACIÓN

El sistema ya tiene el dashboard comercial funcionando. NO lo reconstruyas.
Debes ampliar la lógica actual respetando usuarios, roles, permisos, base de datos y módulos existentes.

El objetivo ahora es proteger la cartera de clientes y controlar exactamente qué información puede ver un vendedor después de cerrar una venta.

==================================================
1. PRINCIPIO DE SEGURIDAD DE CARTERA
==================================================

Un vendedor NO debe tener acceso permanente a todos los clientes que haya vendido históricamente.

Quiero reducir el riesgo de extracción, copia o uso indebido de la base de clientes.

Por lo tanto:

PROSPECTO:
Mientras esté en proceso comercial, el vendedor responsable puede visualizar los datos necesarios.

VENTA GANADA:
Cuando el prospecto se convierte en cliente, comienza una ventana de acompañamiento comercial limitada.

CLIENTE ACTIVO:
El vendedor únicamente podrá visualizar ese cliente durante un máximo de 6 meses desde su activación, sujeto a los permisos definidos.

Después de 6 meses:
- El cliente debe desaparecer automáticamente de la cartera visible del vendedor.
- El vendedor no debe poder encontrarlo mediante buscador.
- No debe aparecer en reportes personales.
- No debe aparecer en listados históricos accesibles al vendedor.
- No debe poder acceder mediante URL directa.
- No debe poder consultar API/endpoints manualmente.
- El backend debe impedir el acceso, no solamente ocultarlo en frontend.

El administrador y los perfiles autorizados sí podrán conservar acceso completo.

La duración de 6 meses debe ser configurable por administrador.

==================================================
2. NO MOSTRAR BASE COMPLETA DE CLIENTES AL VENDEDOR
==================================================

No crear una sección donde el vendedor pueda navegar libremente por toda la base histórica de clientes.

El vendedor debe visualizar únicamente:

A. Sus prospectos activos.
B. Sus oportunidades abiertas.
C. Las ventas recientes dentro de la ventana permitida.
D. Clientes que el sistema le haya asignado temporalmente para una gestión específica.
E. Clientes con cobranza que le corresponda gestionar, solamente mientras la gestión esté activa.

No debe existir una forma sencilla de obtener toda la cartera mediante:

- paginación masiva
- filtros globales
- búsquedas generales
- exportación
- endpoints sin restricción
- descarga CSV/Excel
- impresión masiva

==================================================
3. RESTRICCIONES DE EXPORTACIÓN
==================================================

- Exportar CSV.
- Exportar teléfonos.
- Descargar listados.

- Consultas de cientos/miles de registros.

Si el sistema actual posee exportaciones, aplicar permisos específicos.

Ejemplo:

clientes.exportar

Debe estar deshabilitado para vendedor por defecto.

==================================================
5. COBRANZA ASIGNADA AL VENDEDOR
==================================================

Quiero que cuando un cliente deba una mensualidad, pueda aparecer nuevamente al vendedor responsable para que gestione el cobro.

IMPORTANTE:

El vendedor NO vuelve a tener acceso permanente al cliente.

El acceso es temporal y condicionado a una tarea de cobranza activa.

Ejemplo:

CLIENTE:
Juan Pérez

Estado:
PAGO PENDIENTE

Valor:
$23.10

Días de atraso:
5

Último pago:
01/07/2026

Botones:

LLAMAR
WHATSAPP
REGISTRAR GESTIÓN
MARCAR PROMESA DE PAGO

Cuando la deuda se pague:
el cliente debe desaparecer automáticamente de la bandeja de cobranza del vendedor.

==================================================
6. VENTANA MÁXIMA DE COBRANZA COMERCIAL
==================================================

La gestión de cobranza del vendedor solamente debe estar disponible durante los primeros 6 meses posteriores a la activación del servicio.

Ejemplo:

Fecha de activación:
10/08/2026

El vendedor podría gestionar cobranza hasta:
10/02/2027

Después de esa fecha:

el vendedor deja de ver completamente a ese cliente.

Las futuras cobranzas pasan exclusivamente al área administrativa/cartera, salvo asignación explícita por un administrador.

Esta duración debe ser configurable.

==================================================
